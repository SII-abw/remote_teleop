# 真实硬件接入与验收

siinuc 的 ROS 后端和 USB 相机已启动并完成被动读取验证，没有使能真实机械臂，没有修改或重启现场 ROS 驱动。现场使用的兼容配置见 DEPLOYMENT_SIINUC.md。`hardware_validated=false` 允许监看真机并禁止使能；只改成 true 不能代替现场验收。

现场 `robot.stop_strategy=position_hold` 复用旧 ARX JointState 目标接口：仅在平台实际下发过运动后，停止时锁住新鲜实测位置；反馈过期时保留上一个受限目标。启动不会发关节目标，`stop_confirmed` 只表示连续实测静止，不是驱动制动或断电确认。此兼容模式不能覆盖整个 Python 进程卡死/被杀、ROS 故障或控制器失控；生产安全链仍需下面的驱动确认接口、独立看门狗及实体急停。

## 从臂 ROS 驱动

每臂继续使用 `sensor_msgs/JointState` 状态和目标话题，按配置名称重排为 7 关节。接收状态时验证名称和有限数值，以机器人端单调时钟记录接收新鲜度。此接收时刻不等于设备采样时间；DDS 在受控局域网内仍需验证延迟。

对于 `robot.stop_strategy=driver_ack`，增加或连接 `Arm.stop_topic` 和 `Arm.stop_state_topic`，类型均为 `std_msgs/Bool`：

- `stop=true`：驱动停止执行运动，保持安全姿态或执行经过现场批准的制动策略，禁止自动回零。平台会重复发送停止请求。
- `stopped=true`：硬件确认已停止，持续发布新鲜确认。平台在使能/复位前检查它。
- `stop=false`：明确的使能请求。驱动必须先以当前测量位置预装目标，清除旧缓存，再使能，避免恢复过期目标。
- `stopped=false`：确认已使能。只有新鲜且晚于请求的双臂确认到达后才下发运动目标。
- 驱动/控制器必须自带独立命令看门狗和实体急停。Python 线程无法保证在进程崩溃、GIL 长时间阻塞、内核或网络故障下及时执行停止。

话题名示例 `/left/remote_safety/stop`、`/left/remote_safety/stopped` 只是推荐命名。平台不会假装发布一个现有驱动不订阅的 stop 话题就完成了急停。

## ROS 主臂

沿用参考脚本的模式命令：`JointState.position=[1,0]` 为拖动，`[0,0]` 为位置跟随。默认 `mode_confirmation=topic` 需要每臂 `mode_state_topic` 返回确认，`position[0]` 分别为 1/0，且确认必须晚于本次模式请求。现场 `openeai_graph` 兼容已检查的 OpenEAI 源码：拖动模式创建本臂 joint_targets 回显发布器，位置模式删除它；同时要求对应订阅者仍存在且状态新鲜。不把发出的命令或不会随切换更新的 ctrl_mode 参数当成确认。该判断只适用于此驱动版本，ROS 图发现延迟会导致切换失败并停止，不能视为电机级反馈。

接管：机器人暂停接收策略动作，切换 epoch，核对主从位置 → 主臂拖动模式 → 双臂确认 → 机器人授权 HUMAN_ACTIVE。当前主从残差作为本次接管的偏移，避免第一帧跳变。交还：停止人工动作 → 重新对齐 → 预装当前主臂位置 → 主臂位置模式确认 → 请求新 epoch 的策略动作。

策略模式下反馈来自从臂**测量状态**，不是模型预测动作。主臂反馈有本地速度限制；主臂驱动还必须具备本地力矩、速度、失联和工作空间限制，不能仅依赖网络软件。

## 3D 打印 Sii/Feetech 主臂

通过现有 `lerobot.teleoperators.sii_arm_leader` 驱动适配；关节方向、串口、波特率、ID、关节偏移、夹爪比例和量程可配置。沿用现有原始角度→相对角度映射。

- 上游驱动连接时会关闭力矩；必须先验证机械支撑/重力补偿，防止机械臂掉落。通过 `passive_supported`、`serial_support_validated` 显式声明验收结果。
- 必须有可信的 `leader.calibration_file`，格式为 `{"left":[7个原始电机角度弧度值],"right":[7个原始电机角度弧度值]}`。数据由现场标定流程在规定连接姿态采集，对应上游 `_reference_joint_angles`。不要用全零占位文件冒充标定。
- 启动时与该连接姿态比较，超出 `alignment_tolerance` 拒绝继续。新实现不会接受任意开机姿态然后静默重置参考系。
- 从拖动恢复位置控制前，先读取 Present_Position 并写入 Goal_Position，再打开力矩；读取所有 Torque_Enable 确认后才承认切换成功。
- 正常退出不自动关闭力矩或回零；现场必须定义机械支撑及掉电行为。内置 SiiArmLeader 的私有接口与硬件适配层共同维护；修改相关接口后必须重跑契约测试并重新验收。

## 验收顺序

| 阶段 | 条件与通过标准 |
|---|---|
| 驱动隔离台架 | stop 不回零；独立看门狗触发；旧目标不能在重新使能时执行；左右臂停止/模式确认可区分 |
| 无负载主臂 | ROS 与串口分别验证映射、单位、夹爪、方向、软硬限位、机械支撑、预装目标、重复接管和交还 |
| 单臂低速 | 校准实际限位；验证绝对位置/速度/加速度限制；核对 q/action 日志；没有阶跃跳变 |
| 双臂低速 | 设置双臂碰撞安全区域并由机器人驱动/规划器执行；验证主从误差、相机名称和左右对应 |
| 故障注入 | 断云端/策略/主端/从端连接，过期动作、畸形数值、模式确认缺失、相机掉线、磁盘满、写入阻塞；均保持停止且不自动恢复 |
| 网络与负载 | 在实际 WAN 延迟、抖动、丢包和视频负载下测量控制响应与停止时间；配置值必须来自测量与风险评估 |
| 现场长稳 | 按现场班次运行，记录控制周期分位数、CPU/内存/磁盘、队列、温度、误停和停止时延，复核数据完整性 |
| 发布 | 固定父仓库版本/镜像、Conda 依赖、证书、角色凭据和配置版本；完成值守、现场急停及回滚演练后启用 |

关节限位无法替代自碰撞/环境碰撞检测、力控、人体检测、工作空间安全和功能安全控制器。此版本不包含经过认证的碰撞规划器或实时操作系统保证。双臂生产上线必须由现场控制栈覆盖这些条件。

## 当前软件边界

- 每个 gateway 实例管理一台配置机器人和一个 master。多机器人部署使用独立实例、凭据和端口；未实现车队管理和跨实例调度。
- 录像每次创建一个新的单 Episode 数据集，避免无锁追加和覆盖历史数据。已有数据只读检查，不做自动迁移。
- 关闭 WebRTC 可以使用 JPEG 预览。公网 WebRTC 需要部署 STUN/TURN 并验证恢复；ICE 失败可通过断开重连重新协商，尚无独立 ICE 自动重启流程。
- 推理响应受请求超时和动作源观察年龄限制。慢推理会触发安全保持，不会盲目继续执行无限长历史动作；需要选用满足现场延迟预算的模型、分块时长和网络位置。
- 视频和机器人状态基于本地接收时刻对齐，审计保留真实接收时刻。跨设备硬件时间同步和完整视频离线验收不在本版本内。
- 软件停止是机器人驱动安全链上的一环，无法替代实体急停。真实 ROS/串口、TLS 公网、TURN、长时间耐久和实际策略模型尚需现场测试。
